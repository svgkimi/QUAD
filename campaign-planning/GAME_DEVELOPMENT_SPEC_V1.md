## 1. 먼저 결정할 내용

### 사용자 요청으로 확정된 방향

- 동물 구출은 만들지 않는다. **타임어택 안에서 표시된 목표 블록을 제거**한다.
- 특수 효과를 가진 블록과 새로운 모양의 블록을 확장한다.
- 기능·화면·동작·UX/UI를 승인한 뒤 개발한다. 현재 테스트 앱은 그대로 둔다.
- 캠페인 피스 순서는 매 도전 독립 랜덤. 풀이 순서 고정, 필요한 피스 강제 지급, 실패 횟수에 따른 몰래 보정은 하지 않는다.
- 기존 조작·기본 7종 색·음악·로고·보드 중심 구성 유지. 난이도만 올리는 것이 아니라 같은 난이도의 숙련 판도 둔다.
- 5의 배수는 AI 대전, 10의 배수는 보스라는 흐름 유지. 별 1개로 다음 단계, 별 2~3개는 성과 도전.

## 3. F1 — 목표 블록 타임어택

### 플레이어가 하는 일

**제한 시간 안에 ◇가 표시된 모든 칸을 제거한다.** 일반 줄을 많이 지웠어도 ◇가 남으면 클리어가 아니다. ◇ 한 칸을 목표 1개로 센다. 피스 한 덩어리나 한 줄을 1개로 세지 않는다.

| 상황 | 동작·화면 |
|---|---|
| 목표 없는 줄 제거 | 점수/콤보는 기존대로, 남은 목표 수는 그대로 |
| 목표 2개가 있는 줄 제거 | 남은 목표 -2, 해당 두 칸에서 짧은 제거 강조 |
| 목표 아래 줄 제거 | 목표도 그 칸과 함께 아래로 이동, 수는 그대로 |
| 폭발이 목표를 제거 | 목표 감소. 줄 제거와 겹친 칸을 두 번 세지 않음 |
| 마지막 목표 제거 | 해당 고정의 정산을 끝내고 즉시 클리어, 다음 피스를 조작시키지 않음 |
| 제한 시간 종료 | 실패, `시간 종료 · 목표 2개 남음`처럼 원인과 잔여량 표시 |
| 보드 넘침 | 실패. 막연한 실패 문구 대신 `블록이 위까지 찼어요` 표시 |

목표는 초기 보드의 실제 채워진 칸에만 둔다. 빈칸 표식, 보이지 않는 버퍼의 목표, 제거 불가능한 목표는 콘텐츠 검증 실패다. 목표를 없애기 위해 특정 새 피스 한 종류가 **반드시** 필요한 보드는 1차안에서 제외한다.

### 시작 보드 원칙

- 같은 깊이에서도 목표를 좌우·한쪽·여러 높이에 분산한다. 매번 양끝에만 붙이는 방식에서 확장한다.
- 모든 판에 복잡한 길 찾기를 요구하지 않는다. ‘어느 줄을 지워야 하는지’가 바로 보이는 배치를 우선한다.
- 장애물 층은 한 줄에 1~4개 빈칸을 가질 수 있지만, 해당 준비 보드가 무입력/중앙 DROP 반복만으로 자동 종료되는 사례를 검사한다.
- 목표 아래쪽의 일반 블록도 정리할 이유를 주되, 목표 전부 제거 이후 추가 정리 의무를 숨겨 넣지 않는다.

### 시간·별 경계

- 3/2/1/GO, 정지, 도움말, 앱 숨김 시간은 플레이 시간에서 제외. 복귀 시 명시적으로 계속하기.
- 제한 시간이 남은 상태에서 접수된 고정은 줄·폭발·목표 정산까지 원자적으로 처리한다. 그 정산으로 목표가 0이면 클리어.
- 먼저 시간 종료가 확정된 후 들어온 입력은 무효. 결과 화면 뒤의 입력·RAF는 진행시키지 않는다.
- 이미 유효하게 접수된 마지막 고정의 목표 달성과 다음 피스 스폰 충돌이 겹치면 목표 달성을 우선한다. 이는 현재 캠페인 우선순위와 맞춘다.
- 1별=클리어. 확장 타임어택의 초기 제안은 2별 ≤ 제한×0.8, 3별 ≤ 제한×0.6. 모두 목표 달성이 전제이며 경계값 포함.
- 예: 135초 제한 → 1별 클리어 / 2별 108초 이내 / 3별 81초 이내. 인게임 숫자가 아니라 시작·정지·결과가 같은 기준 데이터를 참조한다.
- 기본 1~50의 별 기준과 기존 최고 별을 이 제안 때문에 바꾸지 않는다.

## 4. F2 — 폭발 블록

### 추천 규칙

**폭발 표시가 있는 칸의 가로줄을 완성하면, 그 칸을 중심으로 3×3 범위의 블록도 제거한다.** 별도 누르기·길게 누르기·스킬 버튼은 없다. 떨어지는 일반 피스의 색과 기능을 몰래 바꾸지 않고 초기 보드의 표시된 칸으로 먼저 가르친다.

```text
폭발 중심과 범위         같은 칸의 두 상태
□ □ □                   폭발 블록: ✳ 모양 표식
□ ✳ □                   목표 블록: ◇ 모양 표식
□ □ □                   1차안에서는 한 칸에 둘을 겹치지 않음
```

표식은 시스템 이모지가 아니라 Canvas/벡터 기호로 그린다. 기본 색은 유지하고 기호·테두리로 구분한다. 플레이어에게 불리한 블록만 늘리지 않고 주변 목표를 함께 지울 수 있는 이득을 준다.

### 고정 한 번의 처리 순서 — 구현 계약

1. 피스를 보드에 고정한 **압축 전 보드**에서 가득 찬 줄 목록을 확정한다.
2. 그 줄에 포함된 폭발 칸들을 시작점으로 수집한다.
3. 각 중심의 3×3을 보드 경계 안으로 잘라 제거 집합에 합친다. 폭발 범위에 다른 폭발 칸이 있으면 이어서 처리한다.
4. 같은 폭발 ID는 한 번만, 같은 칸도 한 번만 처리한다. 첫 확장 콘텐츠의 폭발 수 상한은 3개.
5. 일반 줄 제거 칸 + 폭발 칸의 합집합으로 목표를 제거한다. 아직 남은 목표/폭발 표식만 보관한다.
6. 확정한 일반 줄을 압축한다. 남은 칸과 표식에 같은 좌표 이동을 적용한다.
7. 점수·목표·클리어를 한 번만 정산하고 UI에 하나의 이벤트를 전달한다.

**폭발로 생긴 빈 공간으로 개별 칸이 따로 떨어지는 중력/연쇄 낙하는 추가하지 않는다.** 기존처럼 줄 압축만 일어난다. 폭발 주변 잔여 블록이 떠 보일 수 있으며 이 규칙은 시안의 제거 전/후로 확인받는다.

### 점수와 연출

- 줄 점수·콤보·B2B는 실제 완성한 줄에 대해서만 기존 규칙대로 계산한다. 폭발로 없어진 칸 수를 줄 수로 바꾸지 않는다.
- 폭발 자체의 추가 점수/재화/시간 보너스는 1차안에 없다. 이득은 보드 공간과 목표 제거다.
- 제거 위치의 짧은 테두리/입자 연출 약 120~180ms를 제안한다. 게임 시간·입력을 연출 끝까지 기다리게 만들지 않는다.
- 화면 전체 흰 번쩍임, 강한 추가 흔들림, 음악 교체는 하지 않는다. 기존 음소거/햅틱 설정 준수, 미지원 호스트에서도 가시 피드백 유지.
- 처음에는 폭발 1개만, 익힌 뒤 2개 연쇄, 마지막에 3개까지. 첫 소개에서 새 모양과 결합하지 않는다.

## 5. F3 — 새로운 형태의 피스

| ID | 형태 | 칸 수 | 추천 범위 |
|---|---|---:|---|
| I5 | `■■■■■` | 5 | 1차 개발 |
| L5 | 아래 그림 | 5 | I5 검증 뒤 1차 개발 |
| I6 | `■■■■■■` | 6 | **B1 후속 승인** |

```text
L5 — 이름만 L이 아니라 실제 다섯 칸
■
■
■
■■
```

### 출현과 조작

- 해당 스테이지에 허용된 종류 목록에서 매번 독립·동일 확률 추첨. 기본7+I5면 각 1/8, 기본7+I5+L5면 각 1/9. 확률은 고정 설정으로 공개 가능하며 상황에 따라 몰래 바꾸지 않는다.
- 새 피스를 반드시 N번째에 주거나 NEXT 밖에서 바꾸지 않는다. 매 도전 새 시드, QA 재현 시드만 별도로 사용한다.
- HOLD 한 슬롯·한 피스당 교환 제한, 좌우 이동·내리기·회전·DROP·ghost는 기존 방식 그대로.
- 새 피스를 HOLD한 동안 모양·회전 초기화 정책이 기본 피스와 일치해야 한다. NEXT와 실제 스폰 종류가 같아야 한다.
- 기본7의 색·회전 표는 변경하지 않는다. I5는 I 계열의 기존 청록, L5는 L 계열의 기존 주황을 사용하고 NEXT/HOLD에 `5` 표기로 길이를 보조한다. 칸 수와 실루엣이 주 식별 수단이다.
- 고정/회전 지연 예산은 같은 피스에서 그대로 누적한다. 새로운 크기를 이유로 잠금 예산이 리셋되거나 실패한 내리기가 시간을 연장하면 결함이다.

### 회전·배치 정의 초안

I5와 L5는 5×5 로컬 격자에서 중심 `(2,2)` 기준 90도 회전한다.

- I5 스폰: `(0,2),(1,2),(2,2),(3,2),(4,2)`.
- L5 스폰: `(1,0),(1,1),(1,2),(1,3),(2,3)`.
- 최초 원점은 보드 수평 중앙 기준으로 계산하고 상단 버퍼 안에서 유효하게 스폰한다. 종류별 가로폭 하드코딩 금지.
- 새 피스 전용 회전 보정 후보 제안: `(0,0),(-1,0),(1,0),(-2,0),(2,0),(0,-1)` 순. 양방향 및 180도 모두 명시적인 후보를 검사하고, 하나도 맞지 않으면 회전 실패·위치 불변.
- 기본7의 SRS 표와 새 피스 후보는 분리한다. 새 피스가 기존 T-Spin으로 판정되어서는 안 된다.
- 킥 후보는 확정 밸런스가 아니다. 양쪽 벽·바닥·높은 더미·HOLD 직후·회전 반복 시뮬레이터 검증 후 승인값으로 고정한다.

### 한 번에 5줄/6줄

- I5/I6를 수직으로 놓아 해당 줄들이 실제로 모두 완성된 경우에만 5줄/6줄 제거다. 5칸짜리 피스를 떨어뜨렸다는 이유만으로 달성되지 않는다.
- 기본 1/2/3/4줄의 100/300/500/800점은 유지. **5줄 기본1,200점, 6줄 기본1,600점**을 후속 수치 제안으로 둔다. 레벨·B2B·콤보 적용 순서는 기존과 동일.
- 5·6줄을 별도 분류로 표현하고 `none`이나 4줄로 축소하지 않는다. 4줄 이상은 어려운 클리어(B2B 대상), 첫 성공은 B2B 보너스 없음.
- 폭발 칸을 합쳐 ‘5줄’로 세지 않는다. 새 형태의 점수는 캠페인 결과이며 무한 모드 최고기록에 섞지 않는다.
- **처음부터 한 번에 5줄을 필수 관문으로 삼지 않는다.** 독립 랜덤이므로 필요한 피스가 오지 않을 수 있다. 새 형태 소개는 일반 줄/목표 제거를 목표로 하고, 5줄 성공은 추가 재미로 경험하게 한다.
- 한 번에5/6줄 전용 단일 미션을 원하면 B3로 승인한다. 미출현으로 시간만 낭비하는지 먼저 측정하고, 도입 시 고난도 후반이 아닌 해당 피스 소개 구간에 배치한다. 확률 보정/확정 지급으로 문제를 숨기지 않는다.

## 6. 승인용 화면과 UX/UI

### 유지할 것

QUAD 로고의 현재 서체·그라디언트·중앙 배치, 어두운 배경, 보드 테두리와 기본 블록 색을 유지한다. 터치 패드는 **왼쪽 위 HOLD / 아래 좌·우, 오른쪽 위 내리기 / 아래 회전·DROP**. 새 기능용 일곱 번째 버튼을 만들지 않는다.

### 화면 목록

| 화면 ID | 보여줄 것 | 조작·전환 |
|---|---|---|
| S1 단계 목록 | 단계 번호, 기존 획득 별, 보스/새 규칙의 작은 표식 | 선택 → S2. 공허한 장식 카드/긴 스토리 문구 없음 |
| S2 시작 전 | `스테이지 53`, `목표 블록 8개 제거`, `135초`, 별 조건3칸 | 시작 → 카운트다운 → S3. 새 블록 첫 소개만 그림+한 문장 |
| S3 플레이 | 모드·목표 잔여·남은 시간의 **2줄 HUD**, 보드의 ◇/폭발 표시 | 목표 HUD 탭 → S4. 원래 패드로 플레이 |
| S4 목표/일시정지 | 별 조건과 실제 블록 아이콘의 짧은 안내 | 계속하기는 명시적 재개. 닫기만 하면 정지 유지 |
| S5 성공 | 이번 별, 완료 시간, 다음 별 기준, 다음 단계/재도전 | 1별 이상 다음 해금. DEV는 기록 미저장 표시 유지 |

플레이 HUD 예시 — 설명문 대신 눈에 필요한 숫자만:

```text
┌───────────────────────────────────┐
│ 소리    53 / 80 · 타임어택    정지 │
│          ◇ 8개 남음 · 02:15        │
└───────────────────────────────────┘
  HOLD         10 × 20 보드       NEXT
                ◇  ✳  ◇
  HOLD                           내리기
좌      우                    회전    DROP
```

`53/80`과 모든 수치는 승인 시안 값이다. 현재 앱은 50단계 그대로다. S2에는 ‘8개’라는 시작 목표, S3에는 ‘8개 남음’이라는 남은 값으로 표기를 통일한다. 모드 이름을 `동물 구출`, `특수 블록 모드`로 따로 늘리지 않는다.

### 가독성과 터치

- 가시 보드 10×20 비율·현재 크기를 지킨다. HUD/미리보기를 키우는 대가로 보드를 다시 작게 하지 않는다.
- 새로운 표식은 색만으로 구분하지 않는다. ◇목표, 방사형 기호 폭발, 실제 칸 수를 그린 새 형태.
- NEXT/HOLD는 실제 스폰 방향의 실루엣을 보여준다. 맞지 않는 아이콘을 억지로 잘라 넣거나 가로 피스를 세로 피스로 오해하게 그리지 않는다.
- I5는 기존 레일의 약44px 범위 안에서 **5칸이 각각 최소7px**로 보이도록 설계한다. 정확한 여백은 좌표 검증으로 결정하며 보드와 겹치면 승인 실패.
- NEXT/HOLD 탭의 유효 영역은 최소44×44px. 탭하면 정지 후 큰 실루엣 창으로 확인 가능. 도움말이 저절로 열리거나 터치를 가로채지 않음.
- I6는 같은 레일에서 최소 크기/여백 확보가 어려울 수 있어 B1의 별도 UI 승인 대상이다. 무조건 축소해 넣지 않는다.
- 긴 누름 텍스트 선택/복사 메뉴 방지 유지. pointer와 semantic click 중복 입력 방지, 손가락 벗어남/숨김/정지 때 반복 입력 정리.
- 기본/선택/눌림/비활성/포커스를 구별. 확대 글꼴에서 수치·시작·계속 버튼을 가리지 않음.
- VoiceOver/TalkBack에는 목표 잔여와 결과를 의미 있게 제공하되 프레임마다 시간/보드 전체를 읽지 않음.

확장 진행은 별도 저장해 이전50 전용 앱으로 돌아가도 완료 값이 범위를 벗어나 기록이 초기화되는 문제를 막는다. 실제 출시에서는 기본50 완료 후51을 열고, 개발자 앱에서는 승인된 시험 단계만 자유 진입한다. 저장 실패 시 완료를 날리지 않도록 재시도·낮은 값 덮어쓰기 방지 계약을 유지한다.

### 개발 순서 / 승인 지점

1. **명세 승인**: A1~A7 및 추가 B 항목을 선택. 화면 시안에서 바꿀 점을 먼저 확정.
2. **기술 샘플**: 폭발1판, I5 1판, L5 1판만 개발자 전용 플래그로 구현. 기본50에는 미반영.
3. **동작 승인**: 시뮬레이터에서 폭발 전/후, 양쪽 벽 회전, HOLD/NEXT, 목표/별 결과를 사용자와 확인.
4. **콘텐츠 확장**: 승인된 규칙만51~80 데이터로 구성하고 자동 시나리오·사람 플레이로 조정.
5. **출시 반영 승인**: 저장 호환·실기기·호스트·회귀 검사 후 명시적으로 요청받아 일반 버전에 포함.

특수 규칙 실패를 해결하려고 기존 엔진 전체를 새로 쓰거나 도구/네이티브 런타임 major를 바꾸지 않는다. 필요한 경우 별도 변경안을 먼저 제출한다.

| Q02 | 같은 줄의 목표2개 제거 | 정확히2 감소, 카운터·보드·결과 일치 |

| Q04 | 목표 칸이 줄+폭발 범위에 겹침 | 한 번만 제거, 음수/중복 보상 없음 |

| Q11 | 정지/숨김/잠금·복귀·결과 후 입력 | 숨긴 시간 합산/자동 재개/숨은 플레이 없음 |

| Q14 | 기본50·무한·기본 AI 회귀 | 현재 계약 유지, 새 효과/피스 유입 없음 |
| Q15 | 화면 크기/접근성 검사 | 보드·레일·버튼 겹침/잘림 없음, 표식과 목표 읽기 가능 |

화면 검사 대상: 320×568, 360×640, 393×759, 430×932, 767/768 경계, 844×390, 820×1180, 1280×720. iOS Simulator를 기본으로 실제 기종/OS/빌드와 viewport를 구분해 기록하고, Android·실기기·Toss는 가능한 장비/호스트에서 별도로 확인한다. 사용자가 테스트 중인 앱을 무단 재설치하거나 종료하지 않는다.

자동 시나리오에는 준비 보드·시드·액션·예상 제거 칸 ID·실제 제거 ID·잔여 목표·줄 수·점수·별을 남긴다. 여러 시드 통과를 ‘인간에게 재미있다’나 ‘모든 난수 순서에 해결 가능’의 증명으로 표현하지 않는다. 다음 사람 테스트는 목표 이해, 폭발의 이득/혼란, 긴 피스 오조작, 운 때문에 기다린 시간, 재도전 의향을 구분해 기록한다.

## 11. 승인 기록

현재 상태: **전 항목 미승인**. 채팅에서 `A1~A7 승인`, `A2 폭발 범위 수정`, `B1도 포함`처럼 알려주면 문서에 반영한다. 문서를 열거나 시안의 버튼을 누르는 행동 자체를 개발/출시 승인으로 간주하지 않는다.

| 버전 | 변경 | 승인 |
|---|---|---|
| v0.1 | 목표 제거·폭발·I5/L5, 30단계 후보, 화면/처리 계약과 검증표 | 대기 |

현재 문서는 소스 검토와 자체 설계안이다. 외부 게임의 자산·코드·화면을 복제하지 않았으며 법률/심사 적합성이나 인간 난이도를 보증하지 않는다.
